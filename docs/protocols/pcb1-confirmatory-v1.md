## Question, enrolled methods and selection boundary

Primary question: what pixel Average Precision does the predeclared feature-memory recipe achieve on the full official pcb1 test set after fitting only pcb1 training normals? Enroll exactly two methods: the feature-memory method and a spatial mean reference as a prespecified comparator. Do not select a winner and portray it as an independently validated production model.

Feature extraction, ImageNet weights, input128 normalization, layer2/layer3 pooling/concatenation, RMS nearest-neighbor distance, maximum image score and bilinear map reconstruction follow feature-memory-development-v1. To accommodate a different category size without selecting examples using scores, predeclare k=min(16,floor(8192/N_train)) sampled patches per training image, using the same ID-hash seeded selection. Include every permitted training normal. If k<1, stop for a versioned resource-plan amendment before test access. This category-cap rule needs its own tested implementation/version before execution; the completed 2C implementation intentionally remains fixed at16.

Fit the spatial mean on exactly the same pcb1 training normals using sequential float64 accumulation cast to float32. It uses raw squared RGB residual maps and spatial-mean image score, as in the historical baseline recipe. Do not transplant the Cashew reference, feature bank or thresholds.

The student-teacher proposal is not enrolled in this v1 plan. Adding any model or changing these recipes requires a dated v2 amendment, implementation tests and artifact freeze before test access. Do not use pcb1 test images, masks, labels, scores or metrics to decide whether to enroll it.

## Predeclared near-duplicate and independence gate

Use the historical label-independent candidate rule: dHash64<=4 OR pHash63<=4 OR RGB32 RMS<=0.02 across partitions, LANCZOS thumbnails. Refine candidates with full RGB128 RMS and center-quarter RGB64 RMS plus grayscale Pearson correlation. Strong rule: (full RMS<=0.015 AND crop RMS<=0.025) OR correlation>=0.995. Deterministically inspect the union of first eight full-RMS ranks, first eight crop-RMS ranks, first eight SHA-256 pair ranks and every strong candidate. Store complete candidate lists and review decisions. No model score or defect mask guides selection or visual adjudication.

If a confirmed duplicate/repeated acquisition compromises the evaluation, stop before official metrics. Do not adapt the fitted models using test-driven exclusions under this v1 protocol. A change requires transparent amendment and a new confirmation decision; confirmed leakage cannot be presented as a clean independent benchmark. Broadly similar objects with no confirmed duplication remain a stated uncertainty, not proof of independence. Resolve acquisition provenance where possible; failed/incomplete visual review blocks the gate rather than silently clearing candidates.

## Metrics and fixed geometry

Primary endpoint: pooled pixel AP of feature memory at128x128, using scikit-learn non-interpolated average_precision_score. Also report the predeclared AP difference versus spatial mean. Secondary descriptive endpoints: image AUROC/AP, pixel AUROC, and each model's frozen-threshold TN/FP/FN/TP, precision, recall, F1 and normal FPR. Higher scores mean anomalous; positive class is1. Do not reuse an image threshold as a pixel threshold. AUPRO, Dice/IoU and pixel confusion are deferred unless independently calibrated and preregistered in a pre-access amendment.

RGB preprocessing retains the full frame with bilinear antialiased square resize128. Source mask nonzero IDs become binary and resize nearest-neighbor. Normal targets are derived zeros. Pool all pixels including normal images without subsampling, and report positive/negative counts, prevalence, masks disappearing after resize and geometry limitations. If either class is absent, AUROC and AP are null; division-by-zero rates are null. Retain all samples, including any emptied anomaly masks, with explicit warnings rather than adaptive resizing.

Predeclare exact computation up to eight million pooled pixels and four GiB observed peak working set, with bounded chunks/spill storage as necessary. This requires tested evaluator work before test access; the historical three-million-pixel implementation must not silently subsample or drop records to fit. If metadata counts exceed this ceiling, revise the resource plan before opening test assets. CPU only, four threads, zero workers, batch eight for feature memory; record batch settings per comparator.

Use 1,000 paired image-stratified bootstrap resamples with seed42 for image AUROC/AP differences. Pixel AP uncertainty, if implemented before test access, must resample images or verified acquisition groups, not individual pixels, and preserve paired model samples; otherwise explicitly omit pixel confidence intervals. Where group identities are absent, label all image-based intervals conditional on unverified independence. No deployment claim or formal cross-factory significance claim follows from those intervals.
