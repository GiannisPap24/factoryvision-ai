## Isolation seam and accounting

The accepted Windows supervisor is unchanged. It launches only its fixed synthetic
subprocess probes and exposes no image/model RPC. Generalizing it would introduce a
new security-sensitive execution capability. This phase therefore does not activate
a real worker or add arbitrary subprocess inputs.

SyntheticWorkerDouble is an explicit in-process lifecycle double, with new/suspended/
verified/running/closed transitions. Its verify result is a simulated control-flow
condition, never evidence of a Job Object. All reports say `lifecycle_double_only`.
The OS containment evidence remains the separately accepted Windows/crash tests.
No hard timeout, memory bound or cross-process image transport is claimed for this
synchronous double. Timeout/crash conditions in the new tests are injected signals.

The existing ExecutionLedger is reused directly, with budget five. The complete fixed
plan is checked before work; each condition reserves before preparation/dispatch.
The first reservation precedes the single simulated worker launch. Dispatch is charged
before its first resume and before every inspect request. There is only one session,
five requests on success and one close. No hidden inference-like call occurs.

Preparation/isolation failure retains a reservation without dispatch. Invalid output
or assessment failure retains its charged attempt. Cancellation and timeout retain
the appropriate pre/post-dispatch counts. Unacknowledged resume/worker failure is
UNKNOWN. Every failure stops remaining conditions; there is no retry or new anchor.
Cleanup uncertainty gives run status UNKNOWN even if prior results were received.
The preparation object is single-use, including after failure; another run and a
sixth ledger reservation are rejected before worker creation.

The ledger remains in-memory and cannot survive supervisor death. The prior abort-only
crash policy remains mandatory: no automatic restart/replay, no budget reset, no new
worker on uncertain history. Any future real run requires STOP and separate owner
review after a crash, including if an outer app has lost the complete ledger.
